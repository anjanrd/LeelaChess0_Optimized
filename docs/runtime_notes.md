# Runtime and measurement traps retained from the imported pipeline

These notes carry forward the useful technical rules from the original B README. The imported README itself is archived because its progress paragraph and BT3 input-format assumptions were stale. The actual checkpoint describes itself as `INPUT_CLASSICAL_112_PLANE` (format 1).

1. **Preserve network metadata when wrapping.** `onnx2leela` defaults can silently disagree with a network's input format. Use `quant/wrap.py`, which copies and verifies formats from the source checkpoint. Do not change BT3 to a canonical input format based on the old README's speculation.
2. **Keep the custom calibration implementation.** The imported quantizer uses ORT minmax plus custom percentile/entropy thresholds because ORT's default entropy path was unsuitable. Entropy is a candidate, not an assumed improvement; the frozen recipe selected percentile 99.999 on development data.
3. **Distinguish runtimes.** lc0's onnx-trt integration warns about FP32 behavior with GPU ORT 1.27+. The imported lc0 bundles ORT 1.22.1. Python's ORT 1.31.1 is CPU preparation/selection; its version does not describe lc0's GPU execution. Preserve/check actual DLL/runtime versions.
4. **Precision flags are permissions, not coverage proof.** In this lc0/ORT build, optimize=6 enables FP16; optimize=8 enables INT8 plus FP16, without BF16. Floating operations and sensitive exceptions remain possible. Verify real kernels/layers. The Nsight classifier's name-tagged time fractions are not matmul coverage.
5. **Keep the frozen FEN convention.** Tablebase roots use halfmove 0. The imported notes identify hangs on nonzero-clock FEN-only inputs for some canonical formats; BT3 is classical, but do not change corpus clocks/encoding as housekeeping.
6. **Requested nodes overshoot.** lc0 processes batches and `go nodes N` can exceed N. Preserve Threads/MinibatchSize across fixed-node comparisons, record actual nodes and use them in node-equivalent interpretation.
7. **Printed policy precision is limited.** lc0 stores/prints rounded priors. Study A runs PolicyTemperature=1; search retains the imported defaults. Printed-prior KL is approximate, especially for differences around/below 1e-4; it is not a full-precision logits comparison.
8. **Move overhead changes the time actually searched.** lc0 subtracts MoveOverheadMs from a movetime budget. The adopted Study C sets 20 ms; matches set 50 ms. Record nominal, engine-reported and measured elapsed time, including early stopping.
9. **Use the active encoder.** The default path is `quant/lc0_encode.py`. The original binding policy-index bug affected canonical pawnless transforms; the optional archived `lc0-bindings.patch` concerns that path, not a reason to switch away from the current encoder. Encoder correctness tests are separate from consolidation smoke tests.
10. **Use the imported benchmark positions.** `hw/bench.py` and `hw/batch_sweep.py` use their own fixed halfmove-zero UCI positions and meter energy around searches. Do not replace them with lc0's built-in benchmark corpus during a comparison. Built-in nonzero-clock positions were problematic for canonical nets.
11. **Preserve search differences intentionally.** Study B sets SmartPruningFactor=0 to spend the node budget. Study C/matches keep default smart pruning because they measure the playing configuration. Do not silently equalize them after the fact.
12. **Tablebases never assist search.** Their labels score chosen moves; the match arbiter can adjudicate. Keep SyzygyPath out of the evaluated engine configuration.
13. **Swaps have two bodies.** They isolate policy/value effects at fixed nodes and do roughly twice the network work. Exclude them from speed/energy frontier comparisons.
14. **Sparse zeros do not guarantee sparse kernels.** lc0's current onnx-trt backend does not pass the standalone trtexec sparsity flag. Report lc0 timing separately from sparse-enabled/dense trtexec probes and verify selected tactics before claiming sparse acceleration.
